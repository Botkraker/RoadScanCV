# Handoff: TN segmentation model, 2026-10-04

Read this first in a new conversation. It covers the goal, the current state, what was tried, what went wrong, and the
next steps in priority order. Paths are relative to the repo root `C:\Users\hp\Documents\ComputerVisionDataSet\Road Scan`
(the main checkout, branch `main`: all work below is there, uncommitted).

## 1. Goal

- **Final use:** a phone **behind the car windshield** (dashboard mount), filming the street. The model outlines road damage.
- **Classes shown to the user:** pothole + crack. The model is still trained on all 5 TN classes (pothole, crack, manhole, trash, other).
- **What the model is for right now:** a **teacher** that pre-labels new recordings well enough to grow the dataset
  (later: train a small phone model on that data).
- **Pain point:** hallucinations on walls, cars, the dashboard/glare and plain road, plus flickering shapes.

## 2. The core problem (the most important fact)

**The training data does not match the final camera.**

| | Training frames (`data/tn`) | Final use (`data/raw/tn/*.mp4`, 26/09 clips) |
|---|---|---|
| Camera | handheld or low, outside the car | phone behind the windshield |
| Shape | landscape 1920x1080 | portrait 1080x2288 (8 clips) or square 1440x1440 (2 clips) |
| In frame | street only | red car hood + dashboard in the bottom 40-50%, glass glare |

Everything tried so far (augmentation, a better pretrained model, negatives) works around this gap. The real fix is
**labelled windshield frames**, and 272 of them are ready to correct (section 6, step 1).

## 3. Data

- `data/tn/`: 476 labelled frames (390 train / 86 val), 5 classes, polygon labels (YOLO seg). Labels are noisy (missed objects, wrong classes).
- Split (`tn.py split`): per video, every 5th block of 8 consecutive frames is val, with a 1-frame gap. **Val has only 12 potholes**
  and **no windshield frames**, so val mAP says nothing about the real use case.
- Class `other` = look-alikes that aren't damage: water marks, paint, tyre marks. It is the biggest hallucinator.
- Our `crack` polygons are mesh/fatigue cracking (= "alligator" in uzbtrust's classes).
- `data/tn/images/` also holds 893 **unlabelled** frames: 396 from `20260920_122358` (handheld) and 497 from 6 windshield clips.
- `data/negatives.txt`: **580 hard negatives** (frames where round 1 fired but nothing real is there), picked by hand on
  `data/tn/review/index.html`. 332 handheld (`122358`), 248 windshield.
- The other 272 review frames contain **real damage**; they are pre-drawn in `data/tn/import_review.json` (section 6, step 1).
- Windshield clips (`data/raw/tn/`, 26/09):
  - **Hold-out, never trained on:** `20260926_080755` (square, old town), `20260926_130704` (portrait avenue with real cracks).
  - **Used for negatives:** `081053`, `081645`, `123013`, `125907`, `130111`, `132750`.
  - **Excluded:** `122923` (sky), `130637` (car interior and a person's face, keep it out of any dataset).
- Not versioned yet: the new frames, `negatives.txt`, `review/`, `import_review.json` are outside DVC (`data/tn.dvc` is from before).

## 4. Models

All start from **uzbtrust/smart-road-pci-yolo11** (Hugging Face, YOLO11 detector, 41k road images), turned into a
YOLO11-**seg** model with `train(pretrained=w)`. 649/711 tensors transfer (backbone, neck, box + class head); the mask
branch is new. Our 5 classes sit in uzbtrust's 10 slots: pothole=4, crack=1, manhole=7, trash=8, other=9.

| Run | Setup | Val mask mAP50 | Verdict |
|---|---|---|---|
| `l640_freeze` | yolo11l, 640, backbone frozen (layers 0-9) | 0.291 | **Best by eye** (fewer false alarms). Weights in `runs/l640_freeze/` |
| `l640` | same, not frozen | - | worse by eye |
| `m1024` | yolo11m, 1024, not frozen | - | worse by eye |
| `m1024_freeze` | - | - | skipped |
| `l640_freeze_r2` (in `runs/`) | meant to use the 580 negatives | 0.289 | **Trained WITHOUT negatives** (bug, section 7). Same as round 1. Not a real round 2 |

Augmentations in all runs: `degrees=20, perspective=0.0005, shear=5, scale=0.5, hsv_v=0.4, hsv_s=0.35, copy_paste=0.5`.
Older runs (tn1-tn6, COCO-seg init, yolo11s) top out at about 0.30 val mAP50; see `data.md` section 4.5.

## 6. Next steps, in priority order

1. **Label the 272 windshield frames** (1-2 h, biggest gain). Label Studio, existing TN project -> Import
   `data/tn/import_review.json` -> correct the pre-drawn shapes (many "other"/"manhole" on walls and cars are wrong) ->
   Submit every frame -> export JSON -> `python src/tn.py sync --json <export>`.
2. **Make a small windshield test set so progress is measurable** (recommended, not decided). For example, label about 50 frames from
   the two hold-out clips and score every model on them. Without it, every round is judged by eye on different videos,
   which is a big reason the work felt circular.
3. **Train round 3** = TN labels + the 272 windshield labels + the 580 negatives, `l640_freeze` setup, plus an unfrozen
   twin on a second account (the windshield view may need the backbone to adapt).
   - After `sync`, the 272 frames are labelled, so `pack` puts them into train/val automatically.
   - On the drive: delete every `negatives*.txt`, upload `data/negatives.txt`, upload the new zip and notebook.
   - Colab: new `RUN` name (e.g. `l640_freeze_r3`); cell 3 must print `... (580 negatives)`.
4. **Use it as a teacher:** record windshield video -> `tn.py frames --video ... --weights runs/<best>/weights/best.pt`
   (now keeps portrait shape) -> correct in Label Studio -> repeat. Use the `demo_video.py` filters to judge.
5. Later: decide whether `other` stays. It is 44% of all masks and the main source of hallucinations.

## 7. What went wrong (so it isn't repeated)

- **Old notebook cells 6-7 overwrote `negatives.txt` with an empty file under "Run all"**, so `l640_freeze_r2` trained
  without negatives. Confirmed by behaviour: r2 still fires on 143/150 of its own "negative" frames (round 1: 146/150).
  The new notebook has no such cell and asserts the file isn't empty.
- **`RUN` left at the old value** -> the `DONE` guard skipped training in seconds. A run that "finishes fast" didn't train.
  To retrain a name, set `RESTART = True` once, then back to `False`.
- **Judging by eye on unlabelled, ever-changing videos** made it hard to see progress (step 2 above fixes it).
- `YOLO(cfg).load(w)` silently drops uzbtrust's class head (it goes through an 80-class model). Use `train(pretrained=w)`.
- `resume=True` on a finished Ultralytics run silently restarts from scratch, hence the `DONE` file.
- Drive: uploading a same-named file can create `name (1).txt` instead of replacing it. Delete first, then upload,
  then **Restart session** in Colab (the mount caches).
